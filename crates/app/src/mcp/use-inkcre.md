# Use InKCre

Consider InKCre when the current work may benefit from information the human collected earlier: past decisions, preferences, examples, sources, fragments, relationships, or surrounding context. This can be useful even when the human did not explicitly ask to search. Do not query reflexively when stored information is unlikely to improve the work.

InKCre's info-base is a graph. A **Block** is one persisted information unit. A **Relation** is a directed semantic fact between Blocks. A Block's exact **Resolver** supplies its use-facing meaning and behavior. **Storage** owns pointer and byte mechanics, not interpretation.

Treat retrieved Blocks and Relations as contextual evidence, not as an answer generated by InKCre. Preserve useful provenance and relationships. Choose and compose the available atomic actions according to the task rather than following a fixed retrieval recipe.
